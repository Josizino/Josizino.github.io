Project 001

In development

StintMind

Race-operations platform for amateur endurance racing teams

Problem
Endurance teams with six to eight drivers sharing one car plan fuel, stints, and driver rotation for 7 to 24 hour races on spreadsheets.
Built so far
The security and tenancy foundation, the layer that is expensive to retrofit once real team data exists.
Not started
Telemetry import, the stint engine, and race plans.

Implemented

  • Tenant isolation enforced by PostgreSQL row-level security that fails closed
  • AES-256-GCM envelope encryption, with each ciphertext bound to its team
  • HMAC-SHA256 hash-chained audit log, append-only by database privilege
  • Argon2id passwords and rotating refresh tokens with replay revocation
  • Six team roles, each able to assign only roles below its own
Stated limits of the security model
  • The audit chain detects edits but not truncation of its newest entries.
  • Login rate limiting is per process, not shared across instances.
  • Two pre-authentication tables are not covered by row-level security.

Project 002

Released v1.0.0

fim: File Integrity Monitor

Dependency-free host file integrity monitoring, mapped to MITRE ATT&CK

Problem
An attacker on a host trojanises binaries, drops persistence scripts, loosens permissions, and backdates timestamps. None of it shows in a directory listing.
Approach
Baseline SHA-256 digests with size, mode, and mtime, then classify every later change by kind and severity so the output can drive cron jobs and monitoring probes.
